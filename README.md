# SME Carbon Footprint & Credit Trading

โครงงานรายวิชาการพัฒนาเว็บฝั่งเซิร์ฟเวอร์: เว็บจำลองการบันทึก Carbon Footprint และซื้อขายสิทธิการปล่อยก๊าซเรือนกระจกสำหรับธุรกิจ SMEs พัฒนาด้วย **Node.js + Express + PostgreSQL**

## 1. ที่มาและวัตถุประสงค์

บริษัทต้องทราบว่ากิจกรรม เช่น การใช้ไฟฟ้าหรือน้ำมัน ก่อให้เกิดก๊าซเรือนกระจกเท่าใด และเปรียบเทียบกับสิทธิที่ได้รับในแต่ละรอบปี โครงงานนี้จำลองระบบจัดสรรสิทธิการปล่อยแบบ ETS โดยบริษัทที่มีสิทธิเหลือยื่นขายให้บริษัทที่มีสิทธิไม่พอได้

วัตถุประสงค์ของระบบ:

- บันทึกปริมาณใช้จริงพร้อมเอกสารหลักฐาน และคำนวณเป็นตัน CO₂e
- ให้ Admin ตรวจสอบยอดปล่อยและคำขอขายก่อนมีผลในระบบ
- จัดสรรสิทธิรายปี ซื้อขายสิทธิ และตรวจสอบประวัติย้อนหลัง
- เปิดเผยยอดปล่อยรวมรายบริษัทให้บุคคลทั่วไปดูได้

ระบบเป็น **Demo ทางการศึกษา** โควตาและค่าการปล่อยเป็นข้อมูลจำลอง ไม่ได้เชื่อมกับทะเบียนคาร์บอนหรือระบบบังคับใช้กฎหมายจริง และไม่มีการชำระเงินจริง

## 2. Requirements

- Node.js 18 ขึ้นไป
- npm 9 ขึ้นไป
- Docker Desktop พร้อม Docker Compose
- Git หากดาวน์โหลดด้วย Git

## 3. Install และตั้งค่า

เปิด Terminal ในโฟลเดอร์โปรเจกต์แล้วติดตั้ง dependencies:

```powershell
npm install
```

สร้างไฟล์ตั้งค่าบน PowerShell เฉพาะกรณียังไม่มีไฟล์ `.env`:

```powershell
Copy-Item .env.example .env
```

บน Linux/macOS ใช้:

```bash
cp .env.example .env
```

หากมี `.env` อยู่แล้ว ให้แก้ไฟล์เดิมโดยเก็บค่าที่ใช้อยู่ ค่าเชื่อมต่อเริ่มต้นสำหรับ Docker Compose คือ:

```dotenv
PORT=3000
PGHOST=localhost
PGPORT=5433
PGUSER=postgres
PGPASSWORD=postgrespassword
PGDATABASE=carbon_credit_db
JWT_SECRET=
```

ตั้ง `JWT_SECRET` เป็นค่าสุ่มอย่างน้อย 32 ไบต์ เช่น สร้างค่าด้วยคำสั่งนี้แล้วนำผลไปใส่ใน `.env`:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

ถ้าไม่ได้กำหนด secret ที่ใช้ได้ ระบบจะสุ่มใหม่เมื่อเริ่มแอป ทำให้เซสชันเดิมใช้ต่อหลังรีสตาร์ตไม่ได้ ค่า `PGPORT=5433` ช่วยแยกจาก PostgreSQL ที่อาจใช้พอร์ต 5432 อยู่ หากใช้ฐานข้อมูลภายนอกให้แก้ค่าการเชื่อมต่อให้ตรงกัน

## 4. Start PostgreSQL และ Web App

เริ่มฐานข้อมูลและตรวจสอบสถานะ:

```bash
docker compose up -d
docker compose ps
```

เมื่อ PostgreSQL พร้อมแล้ว เริ่มเว็บ:

```bash
npm start
```

เปิด [http://localhost:3000](http://localhost:3000) หรือใช้ `npm run dev` ระหว่างพัฒนา

Docker รัน `schema.sql` เมื่อสร้าง volume ครั้งแรก จากนั้นแอปรัน migration ที่ยังไม่เคยทำเมื่อเริ่มระบบ โดยบันทึกชื่อ migration ใน `schema_migrations` และเก็บข้อมูลเดิมไว้ การเพิ่มฟีเจอร์จึงไม่ต้องล้างฐานข้อมูล

> การใช้ `docker compose down -v` จะลบข้อมูลใน volume ใช้เฉพาะเมื่อตั้งใจเริ่มฐานข้อมูลใหม่ หากพอร์ต 3000 ถูกใช้อยู่ ให้หยุดแอปเดิมหรือเปลี่ยน `PORT`

## 5. Demo Login และสิทธิการใช้งาน

| Account | Password ตั้งต้น | Role ปัจจุบัน |
|---|---|---|
| `admin@demo.com` | `admin123` | Admin |
| `customer@demo.com` | `customer123` | Company — บริษัท B |
| `partner@demo.com` | `partner123` | Company — บริษัท A |

Customer และ Partner รวมเป็นบทบาท **Company (บริษัท)** แล้ว ชื่ออีเมลเดิมเก็บไว้สำหรับทดลอง ทั้งสองบริษัทซื้อและยื่นขายได้ตามสิทธิของตนเอง

บัญชีเดโมสร้างผ่าน migration และเก็บรหัสผ่านเป็น hash พร้อม salt ใน PostgreSQL รหัสผ่านในตารางใช้ได้จนกว่าจะมีการเปลี่ยนรหัส หน้าเข้าสู่ระบบแสดงรหัสตั้งต้นเพื่อความสะดวกในการสาธิต ระบบยังไม่มีหน้าสมัครสมาชิก

| ผู้ใช้งาน | สิ่งที่ทำได้ |
|---|---|
| Public — ไม่ต้องล็อกอิน | ค้นหารายชื่อบริษัท กรองอุตสาหกรรมและรอบปี ดูยอดปล่อยรวม |
| Company | ยื่นยอดใช้จริงพร้อมหลักฐาน ดูผลตรวจ แก้ข้อมูลบริษัทตนเอง ยื่นขาย ซื้อสิทธิ และดูประวัติของตนเอง |
| Admin | ดูข้อมูลทุกบริษัท ตรวจยอดและคำขอขาย จัดสรรหรือปรับสิทธิพร้อมเหตุผล เปิด–ปิดรอบ และดูประวัติปรับเครดิต |

Frontend ซ่อนเมนูตามบทบาท ส่วน Backend ตรวจ token, role และบริษัทเจ้าของข้อมูลก่อนทำรายการหรือดาวน์โหลดหลักฐาน

## 6. วิธีใช้งานและขั้นตอนหลัก

### 6.1 จัดการรอบและจัดสรรสิทธิ

Admin เปิดแท็บ **จัดการรอบ** ซึ่งเป็นหน้าเฉพาะ `?page=rounds` ระบุปี ค.ศ. และสิทธิเริ่มต้นของทุกบริษัท หน่วยตัน CO₂e แล้วกด **สร้างรอบพร้อมจัดสรรสิทธิ** กำหนดเป็น 0 ได้ หากข้อมูลไม่ครบจะไม่สร้างรอบ

| สถานะรอบ | การทำงาน |
|---|---|
| Reporting | เปิดรับคำขอยอดใช้จริงและคำขอขาย ให้ Admin ตรวจยอดใช้จริงได้ |
| Trading | เปิดซื้อขายและอนุมัติคำขอขาย ยังยื่นและตรวจยอดใช้จริงเพิ่มเติมได้ |
| Closed | เปิดดูข้อมูลย้อนหลัง ไม่รับรายการใหม่ คำขอและประกาศที่ยังค้างถูกยกเลิก |

ในแท็บนี้ Admin เลือกรอบปีเพื่อกด **รับรองยอดปล่อยและเปิดตลาด** หรือ **ปิดรอบและสรุปผล** ตามสถานะของรอบ การสร้างปีใหม่ไม่ได้ลบข้อมูลปีเดิม และไม่ยกสิทธิที่เหลือข้ามปี

### 6.2 ยื่นยอดใช้จริงให้ Admin ตรวจสอบ

1. บริษัทเปิด **ยื่นยอดใช้จริงและยอดปล่อย** บนหน้าหลัก
2. เลือกกิจกรรม กรอกปริมาณรวม วันที่เริ่ม–สิ้นสุดในรอบปีเดียวกัน เลขเอกสาร และหมายเหตุ
3. แนบหลักฐานอย่างน้อย 1 ไฟล์ รองรับ PDF, PNG, JPEG สูงสุด 3 ไฟล์ ไฟล์ละไม่เกิน 2 MB
4. กด **ส่งยอดให้แอดมินตรวจสอบ** คำขอเป็น Pending ยังไม่เพิ่มยอดปล่อยหรือหักสิทธิ
5. Admin เปิด **ยอดใช้จริงรอตรวจสอบ → ดูรายละเอียด** ตรวจหลักฐานแล้วอนุมัติหรือปฏิเสธ หากปฏิเสธต้องระบุเหตุผล
6. เมื่ออนุมัติ ระบบเพิ่มรายการปล่อยตามวันสิ้นสุดช่วงใช้งาน และปรับยอดประจำปี ข้อมูลสาธารณะ และสิทธิคงเหลือในธุรกรรมเดียวกัน

ตัวอย่าง: บิลวันที่ 1–31 มกราคมใช้ไฟ 1,000 kWh คำนวณได้ 0.4999 ตัน CO₂e บริษัทดูสถานะ ผู้ตรวจ เวลา และเหตุผลได้จากรายละเอียดคำขอ และยกเลิกได้เฉพาะคำขอที่ยังรอตรวจ

ระบบกันเลขเอกสารซ้ำของบริษัทเดียวกันและกิจกรรมเดียวกันสำหรับสถานะ Pending หรือ Approved โดยไม่แยกตัวพิมพ์ใหญ่–เล็ก รายการที่ปฏิเสธหรือยกเลิกยื่นใหม่ได้ รายการที่อนุมัติแล้วลบผ่าน API รายการปล่อยเดิมไม่ได้

ข้อมูลปล่อยเดิมก่อนเพิ่มระบบตรวจสอบยังอยู่ในยอดรวม ไม่มีการสร้างหลักฐานหรือประวัติอนุมัติย้อนหลัง

### 6.3 ยื่นขายและซื้อสิทธิ

1. บริษัทกด **ยื่นคำขอขาย** บนหน้าหลัก กรอกจำนวน ราคา รายละเอียด ชื่อผู้ติดต่อ และอีเมลหรือโทรศัพท์ แนบหลักฐานเพิ่มเติมได้
2. คำขอเป็น Pending รอ Admin ตรวจ ยังไม่แสดงเป็นประกาศเปิดขาย
3. เมื่อรอบเป็น Trading Admin อนุมัติได้ถ้ามีสิทธิเพียงพอ ระบบกันสิทธิในประกาศและแสดงสถานะ Open
4. บริษัทอื่นเปิดแท็บ **ตลาด** ค้นหาและเลือกซื้อ กรอกจำนวนแล้วกดยืนยัน ระบบโอนสิทธิทันทีในเดโม โดยใช้ราคาจากเซิร์ฟเวอร์
5. เปิดแท็บ **ประวัติ** เพื่อดูคำขอขาย ผลตรวจ หลักฐาน และธุรกรรมซื้อขาย เจ้าของยกเลิกคำขอ Pending หรือประกาศ Open เพื่อคืนสิทธิส่วนที่ยังไม่ขายได้

```text
สิทธิคงเหลือ = สิทธิที่ได้รับ + ซื้อแล้ว − ขายแล้ว − ยอดปล่อยที่รวมในระบบ
ขายเพิ่มได้ = max(0, สิทธิคงเหลือ − สิทธิที่กันในประกาศ)
ขาดสิทธิ = max(0, −สิทธิคงเหลือ)
```

หากอนุมัติยอดปล่อยเพิ่มหรือลดโควตาจนสิทธิไม่พอสำหรับประกาศ ระบบยกเลิกประกาศ Open ที่เกินยอดโดยเริ่มจากประกาศใหม่กว่า ธุรกรรมที่ซื้อขายเสร็จแล้วคงอยู่

### 6.4 ปรับเครดิตและโปรไฟล์

Admin เปิดแท็บ **จัดการบริษัท** เลือกบริษัทแล้วกด **แก้ไขเครดิต** เลือกเพิ่ม ลด หรือกำหนดยอดใหม่ พร้อมระบุเหตุผล ทำได้ในรอบที่ยังไม่ปิด ระบบเก็บยอดก่อน–หลัง วิธีปรับ ผู้ทำรายการ และเวลา รวมถึงการจัดสรรพร้อมสร้างรอบ ประวัติเริ่มเก็บตั้งแต่เพิ่มฟังก์ชันนี้ ไม่มีประวัติย้อนหลังของการปรับเดิม

Admin และบริษัทกด **ปรับโปรไฟล์** เพื่อแก้ชื่อหรือเปลี่ยนรหัสผ่าน การเปลี่ยนรหัสต้องยืนยันรหัสเดิม รหัสใหม่อย่างน้อย 12 ตัวอักษรและไม่เกิน 256 ไบต์ ระบบออก token ใหม่ให้เซสชันปัจจุบันและยกเลิก token เดิมผ่าน session version

## 7. เทคโนโลยีและเทคนิคฝั่งเซิร์ฟเวอร์

| เทคนิค | ใช้ทำอะไรในโครงงาน | จุดที่อธิบายในการนำเสนอได้ |
|---|---|---|
| Node.js + Express | แยก API routes, middleware และ services | เส้นทาง Request → ตรวจสิทธิ์ → ตรวจข้อมูล → ฐานข้อมูล → Response |
| PostgreSQL + pg | เก็บข้อมูลสัมพันธ์และเรียก SQL แบบ parameterized query | ป้องกันการนำ input ไปต่อเป็นคำสั่ง SQL โดยตรง |
| Authentication / Authorization | JWT แบบ HS256 ตรวจอายุ token และ session version พร้อม role และเจ้าของข้อมูล | แยกการยืนยันตัวตนกับการอนุญาตให้ทำรายการ |
| Password hashing | scrypt พร้อม salt และ timing-safe comparison | ไม่เก็บรหัสผ่านจริงในฐานข้อมูล สุ่ม salt ใหม่เมื่อเปลี่ยนรหัส |
| Transaction และ row lock | ล็อกรอบปีด้วย SELECT FOR UPDATE ก่อนเปลี่ยนยอด อนุมัติ หรือซื้อขาย | ลดปัญหาคำขอพร้อมกันทำให้ยอดผิดหรืออนุมัติซ้ำ |
| Database constraints / indexes | Foreign key, CHECK, UNIQUE และ partial unique index กันเลขเอกสารซ้ำ | ให้ฐานข้อมูลช่วยรักษาความถูกต้องนอกเหนือจากการตรวจใน API |
| View | ets_company_balances สรุปโควตา ยอดปล่อย ซื้อ ขาย และกันสิทธิ | อธิบายที่มาของยอด Dashboard และสูตรคงเหลือ |
| File validation | ตรวจชนิดจากลายเซ็นไฟล์ ขนาด จำนวน และสิทธิ์ดาวน์โหลด เก็บไฟล์เป็น BYTEA | หลักฐานเป็นข้อมูลส่วนตัวของเจ้าของและ Admin |
| Audit history / trigger | เก็บประวัติปรับเครดิตพร้อมเปลี่ยนยอด และป้องกันแก้หรือลบประวัติด้วย trigger | ตรวจสอบว่าใครปรับยอดเท่าไร เมื่อใด และเพราะอะไร |
| Schema migrations | บันทึกเวอร์ชันและรัน migration ที่ยังไม่เคยทำ | เพิ่มตารางหรือข้อกำหนดโดยไม่ต้องเริ่มฐานข้อมูลใหม่ |

Frontend ใช้ HTML, CSS, JavaScript และ Bootstrap แสดงตัวอย่างการคำนวณก่อนส่ง แต่เซิร์ฟเวอร์คำนวณยอดใหม่เองและใช้ข้อมูลบัญชีจาก token ไม่เชื่อยอดหรือบริษัทที่ผู้ใช้แก้ในหน้าเว็บ

## 8. Core API

API ที่ต้องล็อกอินส่ง header `Authorization: Bearer <token>` รายการของบริษัทจำกัดตามเจ้าของข้อมูล ยกเว้น Admin ที่ดูทุกบริษัทได้

| Method | Endpoint | Access / หน้าที่ |
|---|---|---|
| POST | `/api/v1/auth/login` | Public — เข้าสู่ระบบ |
| GET | `/api/v1/auth/me` | ผู้เข้าสู่ระบบ — ตรวจเซสชัน |
| PATCH | `/api/v1/auth/me` | ผู้เข้าสู่ระบบ — แก้ชื่อ |
| PUT | `/api/v1/auth/me/password` | ผู้เข้าสู่ระบบ — เปลี่ยนรหัสผ่าน |
| GET | `/api/v1/ets/public/rounds` | Public — รอบปี |
| GET | `/api/v1/ets/:year/emissions` | Public — ยอดปล่อยรวมรายบริษัท |

- ยื่นยอดใช้จริง: `activity_type`, `amount`, `period_start`, `period_end`, `document_number`, `notes`, `attachments`
- ยื่นขาย: `year`, `amount_tco2e`, `price_per_ton`, `description`, `contact_name`, `contact_email` หรือ `contact_phone` และ `attachments` ถ้ามี

- ซื้อสิทธิ: `listing_id` และ `amount_tco2e` เซิร์ฟเวอร์อ่านราคาและผู้ขายจากประกาศ

## 9. Database และโครงสร้างโปรเจกต์

ฐานข้อมูลปัจจุบันมีมากกว่า 3 ตาราง เพราะเพิ่มบัญชี การจัดสรรสิทธิ และกระบวนการตรวจสอบ:

| ตาราง / View | หน้าที่ |
|---|---|
| companies | ข้อมูลบริษัท อุตสาหกรรม และเป้าลด |
| app_accounts | บัญชี บทบาท บริษัท hash/salt และ session version |
| ets_rounds | รอบปีและสถานะ |
| ets_allocations | สิทธิที่จัดสรรรายบริษัทต่อรอบ |
| emission_submissions | คำขอยอดใช้จริง ช่วงวันที่ เลขเอกสาร และผลตรวจ |
| emission_evidence | ไฟล์หลักฐานของคำขอยอดใช้จริง |
| emission_records | รายการปล่อยที่นำมารวมยอด รวมข้อมูลเดิมและคำขอที่อนุมัติ |
| ets_listings | คำขอขายและประกาศที่เปิดแล้ว |

บัญชีบริษัทอ้างอิง companies การจัดสรรอ้างอิงรอบและบริษัท คำขอยอดใช้จริงที่อนุมัติอ้างอิง emission_records และธุรกรรมซื้อขายอ้างอิงประกาศกับรอบเดียวกัน รายการตลาดจากระบบเดิมที่ไม่มีรอบปีเก็บไว้แต่ไม่แสดงในตลาด ETS

```text
server.js                       เริ่ม Express และรัน migration
schema.sql                      โครงสร้างตั้งต้นและบริษัทเดโม

public/                         หน้าเว็บ CSS JavaScript และไฟล์ภาพ
public/carbonCalculator.js      สูตรและค่าการปล่อยร่วมกัน
src/config/                     การเชื่อมต่อและ migration
src/middleware/authMiddleware.js ตรวจ token และ role
src/routes/                     API บัญชี บริษัท รอบ ยอดปล่อย และตลาด
src/services/                   การคำนวณ hash รหัสผ่าน ไฟล์ และ transaction helpers
```

## 10. Emission Factors และขอบเขตการคำนวณ

ค่าปัจจุบันอยู่ใน `public/carbonCalculator.js` ส่วน `src/services/carbonCalculator.js` โหลดโมดูลเดียวกันมาใช้ฝั่งเซิร์ฟเวอร์ จึงไม่ต้องกำหนดสูตรซ้ำ

| กิจกรรม | หน่วยที่กรอก | Factor ใน Demo (ตัน CO₂e / หน่วย) |
|---|---|---|
| ELECTRICITY — ไฟฟ้า | kWh | 0.0004999 |
| DIESEL — ดีเซล | ลิตร | 0.002708 |
| GASOLINE — เบนซิน | ลิตร | 0.002189 |
| WATER — น้ำ | ลบ.ม. | 0.000207 |

สูตร: ยอดปล่อย = ปริมาณ × Factor ปัดเป็นทศนิยม 4 ตำแหน่ง หน่วยตัน CO₂e โดย 1 ตัน = 1,000 กิโลกรัม

ค่าเหล่านี้เป็นค่าตัวอย่างของ Demo ยังไม่มีการระบุเอกสาร TGO ปีและขอบเขตที่ตรวจสอบแล้ว จึงควรอธิบายข้อจำกัดนี้ในการส่งงาน หากจะอ้างอิงค่าจริงต้องระบุเอกสาร ปี หน่วย และขอบเขตให้ตรงกับกิจกรรม ระบบนี้ยังไม่ได้คำนวณ Carbon Footprint ครบทุก Scope หรือออกเครดิตที่รับรองจริง

## 11. รายการตรวจสอบระบบ


- ล็อกอินถูกและผิด แยกเมนูและสิทธิ์ Admin / Company
- ยื่นยอดโดยไม่มีหลักฐาน วันที่กลับกัน หรือเลขบิลซ้ำ ต้องไม่ผ่าน
- Pending ยังไม่รวมยอด อนุมัติแล้วรวมครั้งเดียว ปฏิเสธต้องมีเหตุผล
- บริษัทอื่นดูคำขอหรือดาวน์โหลดหลักฐานส่วนตัวไม่ได้
- ซื้อเกินยอดประกาศหรือซื้อประกาศของตัวเองไม่ได้
- ลดเครดิตหรืออนุมัติยอดปล่อยเพิ่มแล้วประกาศที่สิทธิไม่พอถูกยกเลิก
- ปิดรอบแล้วไม่รับรายการใหม่ ข้อมูลเดิมยังดูได้
- แท็บจัดการรอบเปิดหน้าเฉพาะ รีเฟรชและย้อนกลับได้ และหน้าเว็บใช้งานบนมือถือได้

โปรเจกต์ยังไม่มีคำสั่ง `npm test` ใน package.json รายการข้างต้นเป็นแนวทางตรวจระบบผ่านหน้าเว็บและ API

## 12. ข้อจำกัดและแนวทางพัฒนาต่อ

- เป็นระบบจำลอง ETS ไม่มีทะเบียนสิทธิจริง การตรวจรับรองภายนอก หรือ payment gateway
- บัญชีเดโมและรหัสตั้งต้นเปิดเผยเพื่อการสาธิต ยังไม่มีสมัครสมาชิกและกู้รหัสผ่าน
- หลักฐานตรวจรูปแบบและขนาดแล้ว แต่ยังไม่มีระบบสแกนมัลแวร์
- Factor และโควตาเป็นข้อมูล Demo ยังไม่มีการจัดการแหล่งอ้างอิงและเวอร์ชัน Factor รายปี
- ไฟล์เก็บในฐานข้อมูล เหมาะกับขนาดเดโม หากมีข้อมูลมากควรพิจารณาที่เก็บไฟล์เฉพาะ
- ก่อนใช้งานจริงควรเพิ่มการทดสอบอัตโนมัติ การสำรองข้อมูล และการตั้งค่า deployment ที่เหมาะสม
